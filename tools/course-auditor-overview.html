Course Polish

AI tools & strategy

A tool that reviews a whole online course in one pass, from competency alignment to accessibility to seat-hour compliance, then fixes what it finds. File in, file out. Nothing leaves your computer.

Open the tool

Goal

Catch the alignment, clarity, consistency, accessibility, and seat-hour gaps in a whole course in one pass, then fix them, so the tedious part is done in minutes and human judgment goes where it actually matters.

Audience

Instructional designers and faculty getting an online course ready for launch or a quality review.

Process, how it works

Export the course from Canvas. That export is an .imscc file, which is really just a zip of HTML. Drop it on the tool, choose what to check, and it opens the package, reads every page, reports what it finds, fixes what it can, and hands you back a new package to import into Canvas. File in, file out.

The checks: due-date pattern for any days and time, learning objectives on every project, alignment to the official course competencies pulled from the Maricopa curriculum, spelling, directions and accuracy, consistent formatting, accessibility to ADA Title II and WCAG 2.1 AA, and seat hours.

It fixes, it does not just complain

This is the part that makes it worth building. Naming a problem is easy. The tool applies a style guide across the entire course: one palette, one typeface, headings in a solid color box, rubric tables with a colored header row. Every color pair is checked against WCAG AA as it goes, so it cannot ship a combination that fails contrast.

It also solves a problem most faculty have quietly given up on. Canvas strips your formatting. Its editor sanitizes HTML on save and throws away style blocks, font links, and orphaned CSS classes, so carefully designed pages arrive plain and nobody can explain why. Only inline styles survive. Everything the tool writes is fully inline, which is why it holds. It also flags the pages where this has already been happening to you, and the web fonts that have been silently failing to load for your students while looking correct in your editor.

Seat hours, and the thing nobody checks

A syllabus promises a student a certain number of hours. Nobody checks whether the course actually contains them. This tool does the arithmetic: it estimates each module, adds them up, and compares the total against the course’s real seat-hour budget, which depends on credits, load hours, and activity type. A three-credit studio that loads at six is not the same workload as a three-credit lecture, and treating them the same is how courses drift out of compliance without anyone noticing. It also catches work assigned twice, which quietly bills students for the same hours in two places.

No server. No account. No data collected.

Nothing is uploaded anywhere. The course package is opened, rewritten, and saved on your own machine. There is no server to send it to, no account to create, no vendor in the middle, and nothing retained. It cannot leak student data because it never receives any and never transmits anything.

That is a design choice, not an accident. Most tools in this category work by shipping your course to somebody else’s cloud. This one does not need to, because unzipping a file and rewriting HTML is something a browser can do by itself. The compliance-critical checks, including whether the required seat-hours language appears verbatim, are string comparisons and arithmetic. No model required, no data sent, and a deterministic answer every time, which is what you want on anything an accreditor will read.
