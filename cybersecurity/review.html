Program Decisions

  • Prerequisites. The security course lists a Linux course as a prerequisite and a Windows or hardware support course as a corequisite. The fast track needs a written program policy from the program director, or it keeps the Linux course and grows to 10 credits.
  • Length. Fourteen weeks is the federal maximum (fewer than 15 weeks of instruction). Week 14 is the last content week, with the capstone, the employer panel and all makeups; nothing is scheduled for the cohort after it, and the college confirms how breaks are counted.
  • Workload. Seven credits in 14 weeks is about 22 hours of work a week. A pilot with real novices sets the final estimates and decides whether working learners need a longer calendar.
  • Lab platform. Choose and price a hosted lab environment, with local Docker as the alternative.
  • Career course approval. Propose Career Launch through curriculum review with its own competencies, and add it to the AAS so all 7 credits stack. Until it is approved, confirm whether a 1-credit special projects version counts toward the AAS.
  • Arizona policy. The state policy is a draft and its occupation list was not published. Confirm that help desk (15-1232) qualifies before applying.
  • Internships. Security operations internships are usually for students near the end of the AAS, so the fast track presents them as a next step, not a promise.
  • Licenses. Confirm that a tuition-bearing credit course is a noncommercial use under the CC BY-NC-SA textbook license.
  • Employers. Take the curriculum to the existing industry advisory committee and collect signed hiring letters from at least two Arizona employers (a design target) before the first cohort.

Planned for the Pilot

This is a prototype. These pieces are outlined or specified but not built, and a pilot with real novice learners builds and times them before any cohort runs.

  • Windows and Microsoft 365 help desk lab. Four tickets and the ticket note standard are outlined in week 10; the lab itself is built, tested on current Windows versions and timed in the pilot.
  • Active Directory practice. A Windows Server evaluation domain in the hosted lab, so learners practice account tasks in a real directory. Until then, resumes do not list Active Directory.
  • Ticketing tool. Logging lab tickets in a free ServiceNow developer instance, if its terms allow course use.
  • Hosted lab images. Linux and Windows images with the weekly seed files and lab tokens.
  • Assessment packets. The five scenario variants for each assessment and their answer keys.
  • Command testing. A timed novice run of every lab command on Windows, macOS, Linux and the hosted lab.
  • Workload. Weeks 11 and 12 run about 25 hours. The pilot decides whether to move the first practice exam earlier as a diagnostic.
  • Networking course plan. The 135-hour credit-hour plan for the networking course, which is outlined here, not built.

Security course OER vetting

Each main source was checked on 25 November 2026 against a five-part quality rubric. Verdicts: Pass (use as assigned), Caution (use with the stated fix), Replace (do not assign; use the named alternative).

Rubric criteria: Accuracy (factual reliability and authority); Currency (date and fit with SY0-801 and current practice); Accessibility (format, captions, navigability; a full WCAG audit is still required); License clarity (reuse terms stated and verified); Reading level (fit for adult career changers at about 10th grade, with support).
