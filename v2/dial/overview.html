Dial Your Course

Project · AI Tools & Strategy · Learning Design

OverviewLive toolBuild Your Course

A Canvas course goes in. What to fix comes back. Each of the four checks runs on its own, or hands off to the next.

Goal

Every online course has to clear a quality bar. At my college that standard is OSCQR, alongside seat time, accessibility, and regular substantive interaction. In practice a faculty member checks it by hand, at the end of a build, against a rubric written for reviewers rather than for the person doing the work. Or nobody checks it at all, which is the more common outcome and not a failure of will: the checking is genuinely tedious and the tools available do not do it.

Dial Your Course takes the course package a faculty member already has, the Canvas export, and returns what to fix. Not a score, and not a grade on the instructor. A list of findings, each one naming the standard it comes from, the place in Canvas where it lives, and what to do about it. The standard is not fixed to OSCQR either. The rules are a list, so the tool can be pointed at whichever rubric an institution actually uses.

Audience

Any instructor building or revising an online course, and the instructional designer or program director who has to review it. The two want different things from the same run, so the output is ordered for the instructor and complete enough for the reviewer. Faculty use the interface. Nobody has to understand the rules underneath to get a usable answer.

Process

Every check is rule-based and contains no AI. That is a design decision, not a limitation of the build. A quality standard is a published list, so checking against it is a lookup. Given the same course, the tool returns the same answer every time, and a finding can be traced back to the sentence in the standard that produced it. A faculty member being told their course falls short deserves that traceability, and an AI model that paraphrases a rubric cannot offer it.

The harder discipline is what the tool refuses to do. A check that cannot compute does not appear in the report, and no standard is reported as satisfied unless it was actually verified. Silence means the tool could not tell, never that the course passed. Anything requiring human judgement is handed back as a task with the exact Canvas path to it rather than guessed at, which is why a real run ends with a short list of things only the instructor can decide.

Nothing is uploaded and nothing is stored. A Canvas course export contains no student data, and the checks run against the package itself.

Tools

1Syllabus Checker1 of 4 · no AIChecks a finished syllabus against program and college requirements, and tells you exactly what is missing. 2Quality Check2 of 4 · no AIRuns a course against a published quality standard and returns what fails, by module, with the fix. 3Style Guide3 of 4 · no AIGenerates Canvas-safe course HTML in a chosen palette, every style inline, because Canvas strips stylesheets. 4Seat Time4 of 4 · no AIEstimates the real time a module asks of a student against what the credit hours allow.

The round trip

The checks are only half of it. Approved changes are written back into the course package and the cartridge is repackaged for reimport, so the loop closes rather than ending in a list somebody retypes by hand. The package is opened, read, rewritten, and rebuilt entirely inside the browser tab. Nothing is uploaded.

Two refusals are built into that step. The tool will not write a package it did not read, so there is no path where it emits a course it never parsed. And the repackaged cartridge is meant for a sandbox, never a live section, which is stated at the button rather than in documentation nobody opens. Anything Canvas alone can do is printed as a short handback list instead of attempted.

Outcomes

The checks have been run against real course packages, not test fixtures. One full audit of AVC 100 returned 28 findings across 34 pages, 27 graded items, and 17 rubrics, sorted into two to fix, eleven to review, and fifteen satisfied. The most useful finding was not a failure: fourteen of twenty-seven graded items carried no course outcome. Defensible in places, and something no instructor had ever been shown before.

Two of the checks have already changed courses. The Style Guide styles every Canvas page in AVC 183 and AVC 248, so a student meets one visual system instead of a different one each week. The workload model writes each module’s estimated hours into that module’s introduction, so students know the commitment before they begin rather than discovering it in week three.

The checks have now been run against about six courses in my department. What has not happened yet is another instructor running it on their own course, unaided, which is the next thing to find out and the reason the interface matters more than the rules do.

Status

Syllabus Checker is built and in use as a standalone tool. Style Guide is built and in use. Seat Time is built and running against a real course. Quality Check is in build, and it is the one carrying the most rules. The four are being folded into one interface.
