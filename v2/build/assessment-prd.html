1. Summary

Takes an assignment a student can finish with a chatbot and returns one they have to perform and defend.

2. Goal

The take-home essay and the multiple-choice exam stopped being reliable the moment students had AI. This is a validity failure, not a matter of taste: those instruments no longer measure the student. Agreeing with that is easy. Rebuilding a real course around it, week after week, is the work.

3. Users and context

Any instructor whose assessments were built for a world without AI, which is most of them. Faculty use the interface, never the underlying method directly.

4. How it works

An assignment goes in. The tool scores it against a vetted framework held in tools/reference/, not against anything a model invented, then proposes a replacement at the same cognitive level. Every suggestion arrives with four choices: apply, edit first, dismiss with a reason, or defer. Nothing is applied automatically.

5. Data, privacy, and governance

No student data and no personally identifiable information. The tool reads course structure and text, never submissions, grades, or rosters. Nothing entered is used to train a model. It is designed to run on district infrastructure with no personal API key in the shipped tool.

6. Design constraints

The tool must be able to say nothing. An assessment that is already resistant returns no suggestion. A tool that always generates something teaches faculty to ignore everything it generates. It must also ask which assessment lane a task belongs to before proposing anything, since an AI-completable assessment is only a defect when the assessment is meant to be secured.

7. Status

In build, and the least finished of the tools. It is also the one worth the most.
