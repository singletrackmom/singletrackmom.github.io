Scenario and task bank

Student journey study

← District barriers study overview

The data backbone of the study: every persona, campus, and task in one matrix, planned but not yet run.

This sheet is a plan and a backbone, not results. The status, result, and severity columns are empty until real runs happen. Nothing here claims a task has been tested. As runs complete, testers fill those columns and the coverage dashboard reads them.

1. What the bank holds

The bank starts from a taxonomy of base tasks spanning the whole student journey: application and admissions, getting an MEID, residency, advising, self-enrollment, financial aid, adding and dropping classes, transcripts, transfer, swirling, veterans benefits, Disability Resources, counseling, basic needs, campus tech, the bookstore, and graduation offboarding. Each base task is a felt need, never a destination.

Every row carries a Scenario ID, the persona, the campus, the journey stage, the one task, the suspected barrier, the tester type, a dependency flag for the advising-tool wave, and empty fields for status, tester, date, result, and severity. Severity is rated 0 to 4, following Nielsen: 0 not a usability problem, 1 cosmetic, 2 minor, 3 major, 4 catastrophic (a student cannot complete the task and would plausibly give up). The full bank lives in the Maricopa scenario-bank workbook alongside the persona library, the task taxonomy, the coverage math, the accounts-we-need list, and a barrier log that mirrors the existing study kit. 2. How the bank scales

  1. Base tasks. 46 tasks cover the whole journey, each written as a problem, not a destination. Twelve are flagged as dependent on the district advising tool (advisor assignment and booking, aid impact at drop, consortium aid).
  2. Multiplied by personas. Each task is run by several personas from the library, because different barriers reveal different failures. This is what lifts the bank toward 500 distinct persona and task scenarios.
  3. Multiplied by ten colleges. Each scenario is attempted at each college, where the local service name and the page layout differ. Five hundred scenarios across ten colleges is about 5,000 task-runs.

Every row carries a tester type, and the written bank seeds it at 91 human and 90 AI. That column is a routing hint, not a staffing commitment. Human testers are volunteers from the Student Support and Success domain, whose members are drawn from all ten colleges. Because a Maricopa account reaches only its holder’s own college, each member is the route to the one campus that member can actually test, and the domain membership is therefore what makes coverage across the ten possible. Volunteers take a single scenario in a single sitting, roughly fifteen minutes, and no fixed tester count is set. Coverage grows by adding personas, tasks, and colleges, which is where new defects come from, rather than by running the same task with more testers, which largely re-finds what is already found. AI testers run the same scenarios in parallel to extend coverage beyond what volunteers can carry, and volunteers cover the login-walled flows at their own campus and validate what the AI finds. The tester-type column changes as capacity changes.

4. The two waves

The district advising tool (Salesforce) is not yet accessible to the domain, so the scenarios that depend on it are deferred to a second wave, to be run during or after that tool’s pilot. This is a stated constraint on completeness, not an omission.

4.1 Wave 1, runs now

  • Everything testable on the live public and student-portal systems today.
  • Apply, MEID, residency, orientation, self-enrollment, financial-aid pages, scholarships, bookstore.
  • Find tutoring, Disability Resources intake, counseling, basic needs, campus tech, transcripts, graduation offboarding.
  • The swirl application and the credit-return path.

4.2 Wave 2, once the district advising tool is accessible

  • Find or get assigned an advisor, with the advisor shown in the student system.
  • Book an advising appointment through the new tool.
  • Understand how dropping a class affects aid, surfaced at the moment of dropping.
  • Confirm that consortium aid covers a class taken at a second college.
