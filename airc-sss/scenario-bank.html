Initiative 2 · the data backbone

Scenario & task bank
Every persona, campus, and task in one matrix

This is the backbone of the scaled study. It starts from a taxonomy of base tasks that span the whole student journey, application and admissions, getting an MEID, residency, advising, self-enrollment, financial aid, adding and dropping classes, transcripts, transfer, swirling, veterans benefits, Disability Resources, counseling, basic needs, campus tech, the bookstore, and graduation offboarding. Each base task is a felt need, never a destination. The bank multiplies those tasks by persona and by the ten colleges to reach roughly 500 distinct persona-and-task scenarios and about 5,000 task-runs. Every row carries a Scenario ID, the persona, the campus, the journey stage, the one task, the suspected barrier, the tester type, a Salesforce-dependency flag, and fields for status, tester, date, result, and severity. The full bank is the spreadsheet; a sample is shown below.

This sheet is a plan and a backbone, not results.
The status, result, and severity columns are empty until real runs happen. Nothing here claims a task has been tested. As runs complete, testers fill those columns and the coverage dashboard reads them. The downloadable workbook, Maricopa_Scenario_Bank.xlsx, holds the full bank with the persona library, the task taxonomy, the coverage math, the accounts-we-need list, and a barrier log that mirrors the existing Study Kit.

How the bank scales Base tasks × personas × ten colleges

Step 1

Base tasks

46 tasks covering the whole journey, each written as a problem, not a destination. Twelve are flagged as Salesforce-dependent (advising assignment and booking, aid-impact-at-drop, consortium aid).

Step 2

× personas

Each task is run by several personas from the library, because different barriers reveal different failures. This is what lifts the bank toward 500 distinct persona-and-task scenarios.

Step 3

× ten colleges

Each scenario is attempted at each college, where the local name and page layout differ. 500 scenarios across 10 colleges is about 5,000 task-runs.

Humans run about half, AI testers run about half.
The plan splits roughly 250 scenarios to human testers and 250 to AI testers, each set spread across the ten colleges. In this written bank the split is already seeded: 91 scenarios to humans and 90 to AI. AI testers walk the public, no-login paths at scale; human testers cover the login-walled flows and validate what the AI finds. The Tester Type column flips as capacity changes.

The two waves What we can run now, and what waits on Salesforce

Wave 1 · runs now

  • Everything testable on the live public and student-portal systems today
  • Apply, MEID, residency, orientation, self-enroll, financial aid pages, scholarships, bookstore
  • Find tutoring, DRS intake, counseling, basic needs, campus tech, transcripts, graduation offboarding
  • The swirl application and credit-return path

Wave 2 · after Salesforce

  • Find or get assigned an advisor (advisor shown in SIS)
  • Book an advising appointment through the new tool
  • Understand how dropping a class affects aid, surfaced at the moment of dropping
  • Confirm consortium aid covers a class at a second college
